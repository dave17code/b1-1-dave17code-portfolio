| 4 | 맨 위 버튼 클릭 | 페이지 처음으로 이동 |

폼 성공은 실제 메일 발송이 아닙니다. 화면에서 그 사실을 안내합니다.

## API 에러와 재시도 시연

1. Chrome 개발자 도구의 Network에서 GitHub API 요청을 찾습니다.
2. 요청을 오른쪽 클릭하고 **Block request URL** 또는 해당 버전의 **Request conditions** 기능으로 이 API 요청만 차단합니다.
3. 개발자 도구를 연 상태로 페이지를 새로고침합니다.
4. **프로젝트를 불러올 수 없습니다**와 **다시 시도** 버튼을 확인합니다.
5. 차단을 해제하고 **다시 시도**를 누릅니다.
6. 실제 카드가 다시 표시되는지 확인합니다.

사이트 전체를 오프라인으로 바꾸면 HTML 자체가 로드되지 않을 수 있으므로 **GitHub API 요청만** 차단합니다. 로딩 상태는 해당 API 요청에 느린 네트워크 조건을 적용해서 확인할 수 있습니다. [Chrome 요청 조건 공식 안내](https://developer.chrome.com/docs/devtools/request-conditions)

빈 배열과 403은 제작 단계에서 별도의 응답 시뮬레이션으로 검증했습니다. 빈 상태를 시연하려고 실제 GitHub 저장소를 삭제하거나 403을 만들기 위해 반복 요청하지 마세요.

## 구현 설명을 요청받으면

- **테마**: 클릭 → `state.theme` 변경 → `renderTheme` → `data-theme` 변경 → CSS 변수 적용, localStorage 저장
- **API**: 요청 → `loading` → 응답 검사 → `success / empty / error` → `renderProjects`
- **폼**: 입력 → 값과 오류 상태 변경 → 해당 필드 아래 오류 표시 → 제출 시 전체 확인
- **메뉴**: 클릭 → `menuOpen` 변경 → `active` 토글과 `aria-expanded` 갱신

API가 실패해도 다른 섹션, 메뉴, 테마, 폼은 계속 사용할 수 있습니다.
